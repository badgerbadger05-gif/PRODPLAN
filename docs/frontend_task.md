# Задача для фронтенд-разработчика: Обновление фильтров в интерфейсе планирования

## Описание
В бэкенде были внесены изменения в логику фильтрации данных планирования. Ранее фильтрация производилась по полю `bucket_date`, теперь же используется поле `start_date`. Это изменение затрагивает несколько ключевых функций:

1. `get_run_production` - основная функция получения данных о производственных заказах
2. `get_run_production_grouped` - функция получения сгруппированных данных о производственных заказах

Также была удалена функция `get_run_production_agenda_day`, которая использовалась для получения данных о заданиях на конкретный день.

## Что нужно сделать

### 1. Обновить фильтры в интерфейсе
- Заменить все ссылки на параметр `bucket_date` на `start_date` в компонентах фильтрации
- Обновить названия полей в формах фильтрации (например, "Дата начала" вместо "Дата бакета")
- Проверить корректность работы всех фильтров после изменений

### 2. Удалить функциональность "Задание на день"
- Удалить вкладку или раздел, связанный с "Заданием на день" 
- Убрать соответствующие пункты меню или навигации
- Обновить экспортные функции, убрав параметр `day_date`

### 3. Обновить экспортные функции
- В функциях экспорта данных убрать параметр `day_date` и всю связанную с ним логику
- Обновить названия колонок и заголовков в соответствии с новой терминологией

### 4. Проверить совместимость
- Убедиться, что все существующие функции продолжают работать корректно
- Проверить отображение данных в таблицах и диаграммах
- Протестировать различные комбинации фильтров

## Важные моменты
- Все изменения касаются только фильтрации по дате начала (`start_date`) вместо даты бакета (`bucket_date`)
- Логика группировки и другие аспекты остались без изменений
- При возникновении вопросов обращаться к бэкенд-разработчику

## Сроки
Задачу желательно выполнить в ближайшие 2-3 дня для обеспечения согласованности системы.
