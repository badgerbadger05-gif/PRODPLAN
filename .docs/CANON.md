# КАНОН PRODPLAN — конституция структуры. Нарушение = отклонённая волна.

Этот файл — закон для ЛЮБОГО агента и человека, пишущего код в этом репо.
Прочитай его ДО первой строчки кода. Он короткий намеренно. Если твоя задача
не влезает в канон — останови работу и подними вопрос владельцу; НЕ пиши рядом.

## Принцип

**Источник истины у каждой величины — ровно один.** Одно ядро на домен.
Новая функциональность = РАСШИРЕНИЕ канонического ядра, никогда — параллельная
реализация. «Своя маленькая копия» уже стоила проекту двух суток работы двух
моделей (см. PRODPLAN/ledger-truth-audit-2026-07-25.md: 4 движка исполнения,
5 реализаций витринной математики, 3 журнала из 3 таблиц одного смысла).

## Реестр канонических ядер

| Домен | Единственный источник | Канонические модули |
|---|---|---|

| Остаток на дату | `visible_sle_query(cutoff)` / running balance `qty_after` | `physical_visibility.py`, `physical.py` |
| Резервы и исполнение | `ReservationEvent` → `fold` → **`ReservationEntry`** (единственный кэш realized/covered/uncovered) | `item_ledger/reservation.py` (чистая математика), `reservation_ledger.py` (ORM) |
| Атрибуция фактов | FIFO старший-план-первым, оси make/consume/buy симметричны (§2.5/§2.6) | `historical_replay_core.py` (+persistence), `supplier_receipt_allocation.py` |
| Заморозка | `mrp_freeze.py`: пул строится ОДИН раз, базис — исторический SLE-баланс, net после заморозки неизменяем (G5) | `mrp_freeze.py`, `pool_key_for` — единственная точка расширения пулов |
| Истина/поколения | `LedgerGeneration` + `PlanningTruthState`, fail-closed | `generation_lifecycle.py`, `obligation_refresh_orchestrator.py`, `obligation_refresh_publish.py`, `planning_truth.py` |

## Пять правил

1. **Запрет дублей.** Прежде чем писать функцию/таблицу/сервис — grep реестра
   выше. Если величина уже вычисляется — ЧИТАЙ её источник. Второй вычислитель
   той же величины запрещён, даже «временный», даже «диагностический», даже
   «за флагом». Кросс-валидатор двух копий — тоже дубль.
2. **Расширяй канон, не обходи.** Канон не умеет нужного → меняется КАНОН
   (с тестами и записью в decisions-log), а не появляется соседний путь.
   Точки расширения помечены в ядрах (напр. `pool_key_for`).
3. **Легаси не консервируется — удаляется.** Замена пути = снос старого в той
   же волне. Никаких «оставим за флагом на всякий случай» без решения владельца
   и даты сноса.
4. **Проекция ≠ пересчёт.** Читатели (журналы, списки, карточки, кокпиты)
   не содержат бизнес-математики. Если читателю нужна новая цифра — её
   вычисляет ядро и кладёт в кэш/снимок; читатель только показывает.
5. **Решения владельца — только в `PRODPLAN/mrp-decisions-log.md`.** Код,
   противоречащий записанному решению, — дефект, даже если «работает».

## Механическая проверка (обязательная часть CI)

`tests/test_canon_invariants.py` — реестры-инварианты (падают при появлении
дубля; расширение реестра = осознанный дифф этого файла в ревью):

- писатели `ReservationEvent` — фиксированный список модулей;
- писатели OData в 1С (`client.post`) — фиксированный список;
- вычислители available/projected/NFP — только `reservation.py`
  (grep-паттерны формул по кодовой базе);
- читатели `ItemWarehouseStock` в планировочных путях — пустой список
  (только legacy-стейджинг синка);
- `net_required_qty` присваивается только в `_freeze_one_run`;
- запрещённые импорты снесённых движков.
