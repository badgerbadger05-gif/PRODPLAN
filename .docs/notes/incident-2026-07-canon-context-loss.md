Он объясняет, почему действуют правила из «Выводов», и не подлежит удалению

## Что произошло

Ночью 25→26.07 владелец с моделью зафиксировал структурную истину проекта:
кодовая половина — свод исполнения к единому ledger-пути (`bec392ac`),
документальная — CANON.md v1 с якорями на доки владельца (`a97384b0`,
26.07 01:24).

Через 12 часов, 26.07 13:59, другая модель (Claude Opus 4.8, контекст 1M,
коммит `8c8bfdb2`) выполнила «консолидацию» в обратном направлении:
затащила в контекст весь код разом — включая легаси, которое v1 объявляла
дефектами, — и переписала канон и документацию «в соответствие коду».
Снесены архив (19 файлов) и 6 живых доков, потеряны §-якоря на журнал
решений и урок аудита 25.07.

Далее цепочка вторичных повреждений:

- 27.07 `3953611a` — канон-гейт горел красным на каждом пуше (тест искал
  журнал решений по абсолютному пути рабочей станции `/home/ivan/…`);
  вместо возврата журнала в репо проверки сделали молчаливыми — авария
  закрепилась как норма.
- 29.07 `06320154` — журнал привезли в `.docs/notes/`, но указатели

  его никто не находил.
- Всю неделю агенты читали канон → шли по мёртвому пути → не находили
  истину → «чинили» по догадкам из кода, по кругу. Решения владельца
  при перезаписи фиксировались с искажениями (пример: «PRODPLAN не пишет

  оператора» — исправлено журналом §12).

## Корневые причины

1. **Направление code → canon.** Намерение выводилось из кода, при том что
   код содержал легаси-дефекты. Документация стала слепком багов.
2. **Огромный контекст без ограничения направлением.** Современные модели
   держат в окне всю кодовую базу; 1M-контекст позволил «согласовать» доки
   со всем легаси за один проход. Сила контекста без правила «канон → код»
   умножает ошибку, а не истину.
3. **Машинно-зависимые пути как указатели истины.** Абсолютный путь одной
   машины сделал высший документ недостижимым на других машинах и CI.
4. **Молчаливые пропуски проверок.** Тест, который пропускает отсутствующую
   истину без шума, узаконивает её отсутствие.
5. **Противоречия внутри корпуса не отслеживались.** Канон, журнал, тест и
   привезённые копии говорили разное; никто не вёл реестр расхождений — и
   каждый агент разрешал их заново в свою сторону.

## Выводы (правила владельца, действуют бессрочно)

1. **Направление только канон → код.** Консолидация документации из кода
   запрещена. Код, противоречащий докам, — легаси-дефект, а не замысел.
2. **Современные модели держат огромные контексты** — тем важнее правило 1:
   модель, видящая весь код разом, обязана мерить его каноном, а не
   переписывать канон под него.
3. **Документация не должна противоречить самой себе.** Обнаруженное
   противоречие между документами — блокер: работа останавливается, пока
   расхождение не согласовано с владельцем.
4. **Все расхождения отслеживаются и согласовываются явно** — реестром
   разночтений (образец — canon-reconciliation-2026-07-30): каждая позиция
   получает вердикт «восстановить / сохранить / вопрос владельцу», ничего
   не разрешается молча.
5. Никаких абсолютных машинных путей в документации; вся истина — в
   репозитории. Проверки истины падают громко, молчаливый пропуск запрещён.
