# Периодный план

Периодный план — единственный пользовательский источник планового выпуска.

## Состояния

```text
draft -> fixed -> closed
```

- `draft` редактируется и может быть удалён;
- `fixed` неизменяем и участвует в резервах и очереди сборки;
- `closed` не участвует в рабочих очередях, но остаётся историей.

Возврата фиксированного плана в `draft`, повторной фиксации и повторного MRP
нет.

## Матрица

План хранит выпуск готовых изделий по срокам. До фиксации пользователь может
редактировать строки и количества. После фиксации вся матрица read-only.

## Фиксация

Одно действие «Зафиксировать» атомарно:

1. проверяет непустой план и данные BOM;
2. сохраняет неизменяемый выпуск;
3. один раз разворачивает BOM;
4. фиксирует полный резерв каждой номенклатуры;
5. распределяет наличие по живым резервам oldest-first;
6. фиксирует потребность пополнения;
7. направляет `make/buy` в соответствующий журнал;
8. добавляет верхнеуровневый выпуск в общую очередь сборки;
9. публикует согласованный снимок одного поколения Ledger.

Отдельных кнопок «MRP-снимок», «Ре-аллокация» и «Создать программу барабана»
нет.

## Просмотр выполнения

План показывает две независимые группы показателей.

### Пополнение

Для каждой BOM-позиции:

- полный резерв;
- покрытие наличием на момент фиксации;
- исходную потребность пополнения;
- физически полученное пополнение;
- остаток потребности;
- процент выполнения пополнения.

### Выпуск

Для каждой верхнеуровневой строки:

- исходный плановый выпуск;
- принятый физический выпуск этого плана;
- остаток выпуска;
- текущее положение в очереди сборки и барабане.

Покрытие деталей не является выпуском готового изделия. Запуск заказа не
является ни поступлением, ни выпуском.

## Новый план

Если старый план недовыполнен, он остаётся живым со своими резервами и
остатком выпуска. Новый план создаёт новые резервы и новые строки очереди.
Старый план имеет FIFO-приоритет.

## Закрытие

План закрывается только явно. При закрытии:

- активные резервы удаляются из рабочего FIFO;
- незакрытые строки удаляются из очереди сборки;
- снимок сохраняет исходные цифры и недовыполнение;
- незакрытый остаток не переносится в другой план автоматически.

## UI-инварианты

1. Открытие страницы ничего не пересчитывает.
2. Все цифры принадлежат одному принятому поколению и cutoff.
3. При недоступном Ledger показатели факта показываются как `unavailable`.
4. UI не суммирует заказы для вычисления выполнения.
5. История плана не подменяется текущими активными резервами.
