# PRODPLAN — правила для агентов

## Иерархия истины (нарушение = худшая ошибка в этом проекте)

1. Слова владельца в текущем разговоре.
2. `.docs/CANON.md` (словарь, реестр канонических владельцев, «Запрещено») и контракты `.docs/*.md`.
3. Код. Код, противоречащий докам, — **легаси-дефект, а не замысел**. Намерение никогда не выводится из кода.

Направление только **канон → код**. «Консолидировать» доки из кода (code → canon) запрещено — так однажды легаси-баг закрытия заказов стал задокументированным поведением, и три волны агентов его «чинили» в неверную сторону.

## Перед доменной правкой

- Прочитай `.docs/CANON.md` целиком (~150 строк) и контракт своей области:
  `item_ledger.md`, `planning-truth-contract.md`, `one_c_export_from_prodplan.md`
  (матрица направлений записи 1С), `reservation-replenishment-core.md`,
  `assembly-queue-and-drum.md`, `shelves-buffers-and-mechshop-pull.md`.
- Новая логика сначала ищется в реестре канонических модулей CANON.md.
  Второй движок / второе хранилище / вторая формула той же сущности — запрещены.
- Факт выпуска — это поступление на склад. Оно гасит потребность и не значит больше ничего.
  Состояние заказа 1С PRODPLAN не пишет никогда (создание заказа командой из PRODPLAN — да; состояние — только read-back).

## Если семантика неочевидна

Один вопрос владельцу одной строкой — вместо волны правок по догадке из кода.
