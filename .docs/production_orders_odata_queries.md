# Запросы к 1С (OData) для проверки учёта активных заказов на производство

Цель: выяснить, как получать:
1) список **активных** заказов на производство (не «Завершен»);
2) их **остатки к выпуску** по позициям (`remaining_qty = ordered_qty - produced_qty`).

Тестовый кейс: заказ **000070** (частично выполнен).

## Предпосылки (метаданные)
- Заказ на производство: `Document_ЗаказНаПроизводство` — см. [`output/odata_metadata.xml:23212`](output/odata_metadata.xml:23212).
- Состояние заказа (для проверки «Завершен») хранится через ссылку `СостояниеЗаказа`:
  - `СостояниеЗаказа_Key` — [`output/odata_metadata.xml:23265`](output/odata_metadata.xml:23265)
  - navigation `СостояниеЗаказа` — [`output/odata_metadata.xml:23384`](output/odata_metadata.xml:23384)
- Факт выпуска, напрямую связанный с заказом: `Document_СборкаЗапасов` содержит `ЗаказНаПроизводство_Key` — [`output/odata_metadata.xml:13151`](output/odata_metadata.xml:13151)

## Как пользоваться
1) Подставь базовый URL (свой стенд 1С):
   - `{{BASE}}` = `https://<host>/<base>/odata/standard.odata/`
   - Примеры итоговых ссылок ниже даны как `{{BASE}}<EntitySet>?...`
2) Открывай ссылки в браузере.
3) Копируй JSON-ответ целиком.

Рекомендация: почти везде добавлен `?$format=json`.

# A. Найти заказ 000070 и его состояние

## A1) Получить заголовок заказа по номеру (Ref_Key нужен дальше)
**Ожидаем:** в ответе 1 запись с `Ref_Key`, `Number`, `Date`, `Posted`.

`{{BASE}}Document_ЗаказНаПроизводство?$format=json&$select=Ref_Key,Number,Date,Posted,DeletionMark&$filter=Number eq '000070'`

## A2) Посмотреть состояние заказа (через expand)
**Ожидаем:** в ответе внутри `СостояниеЗаказа` будет человекочитаемое название/описание (часто поле `Description`).

`{{BASE}}Document_ЗаказНаПроизводство?$format=json&$select=Ref_Key,Number,Date,Posted,СостояниеЗаказа_Key&$expand=СостояниеЗаказа&$filter=Number eq '000070'`

## A3) (Опционально) Найти GUID состояния «Завершен»
Если есть любой завершённый заказ, подставь его номер вместо `000070` и посмотри `СостояниеЗаказа_Key`.

`{{BASE}}Document_ЗаказНаПроизводство?$format=json&$select=Ref_Key,Number,СостояниеЗаказа_Key&$expand=СостояниеЗаказа&$filter=Number eq '000070'`

После того как известен `{{DONE_STATE_KEY}}` (GUID состояния «Завершен»), можно строить фильтр активных:

`{{BASE}}Document_ЗаказНаПроизводство?$format=json&$select=Ref_Key,Number,Date,Posted,СостояниеЗаказа_Key&$filter=DeletionMark eq false and (СостояниеЗаказа_Key ne guid'{{DONE_STATE_KEY}}')`

# B. Заказано (ordered_qty) по позициям заказа

## B1) Забрать табличную часть «Продукция» у заказа 000070
Сначала возьми `{{ORDER_REF_KEY}}` из ответа A1.

**Важно:** ниже используются EntitySet табличной части, который в метаданных есть как `Document_ЗаказНаПроизводство_Продукция` — см. [`output/odata_metadata.xml:23409`](output/odata_metadata.xml:23409).

`{{BASE}}Document_ЗаказНаПроизводство_Продукция?$format=json&$select=Ref_Key,LineNumber,Номенклатура_Key,Характеристика_Key,Количество,Спецификация_Key,Этап_Key&$filter=Ref_Key eq guid'{{ORDER_REF_KEY}}'`

Если запрос ругается на отдельные поля (зависит от конфигурации/версии), сделай более простой:

`{{BASE}}Document_ЗаказНаПроизводство_Продукция?$format=json&$select=Ref_Key,LineNumber,Номенклатура_Key,Количество&$filter=Ref_Key eq guid'{{ORDER_REF_KEY}}'`

# C. Выпущено (produced_qty) по заказу через «Сборка запасов» (схема 1)

## C1) Найти все документы «Сборка запасов», привязанные к заказу 000070
Сначала возьми `{{ORDER_REF_KEY}}`.

`{{BASE}}Document_СборкаЗапасов?$format=json&$select=Ref_Key,Number,Date,Posted,DeletionMark,ЗаказНаПроизводство_Key&$filter=ЗаказНаПроизводство_Key eq guid'{{ORDER_REF_KEY}}'`

## C2) Забрать «Продукцию» по найденным сборкам (выпуск)
Вариант 1 (через отдельный EntitySet табличной части):

`{{BASE}}Document_СборкаЗапасов_Продукция?$format=json&$select=Ref_Key,LineNumber,Номенклатура_Key,Характеристика_Key,Количество,Спецификация_Key&$filter=Ref_Key eq guid'{{ASSEMBLY_REF_KEY}}'`

Где `{{ASSEMBLY_REF_KEY}}` — `Ref_Key` из ответа C1 (запусти для каждой сборки).

Вариант 2 (через expand, одной пачкой):

`{{BASE}}Document_СборкаЗапасов?$format=json&$select=Ref_Key,Number,Date,Posted,ЗаказНаПроизводство_Key&$expand=Продукция&$filter=ЗаказНаПроизводство_Key eq guid'{{ORDER_REF_KEY}}'`

### Как проверяем частичное выполнение
1) Из B1 получаем `ordered_qty` по каждой номенклатуре.
2) Из C2 суммируем `Количество` по каждой номенклатуре как `produced_qty`.
3) Считаем `remaining_qty = max(ordered_qty - produced_qty, 0)`.

Отдельно решаем правило: учитывать ли только `Posted == true` у `Document_СборкаЗапасов`.

# D. Альтернатива (схема 2): проверить регистр «Выпуск продукции»

Идея: если регистр `AccumulationRegister_ВыпускПродукции` даёт устойчивый «факт выпуска», его можно использовать как источник `produced_qty`.

Проблема: в видимом фрагменте метаданных у записи регистра не видно поля `ЗаказНаПроизводство_Key` (прямой привязки к заказу).

## D1) Выгрузить несколько последних записей регистра (для просмотра полей)
`{{BASE}}AccumulationRegister_ВыпускПродукции_RecordType?$format=json&$top=50&$orderby=Period desc&$select=Period,Recorder,Recorder_Type,Номенклатура_Key,Характеристика_Key,Партия_Key,Спецификация_Key,Количество,КоличествоПлан`

Что ищем в ответе:
- есть ли поле, по которому можно однозначно привязать выпуск к конкретному заказу на производство (например `ЗаказНаПроизводство_Key` или эквивалент);
- если нет — какие есть кандидаты (`Партия_Key`, `Recorder` + `Recorder_Type`, связка со `Document_СборкаЗапасов`).

## D2) Попытка связать регистр с «Сборкой запасов» через Recorder
Если в D1 видно, что `Recorder`/`Recorder_Type` соответствуют документу сборки, то можно:
1) из C1 взять `Ref_Key` сборки;
2) отфильтровать записи регистра по `Recorder == '<ref>'` и `Recorder_Type == '<type>'`.

Пример (поля `Recorder` и `Recorder_Type` в регистровых таблицах видны в метаданных):

`{{BASE}}AccumulationRegister_ВыпускПродукции_RecordType?$format=json&$select=Period,Recorder,Recorder_Type,Номенклатура_Key,Количество&$filter=Recorder eq '{{ASSEMBLY_REF_STRING}}'`

Где `{{ASSEMBLY_REF_STRING}}` — строковое представление `Ref_Key` сборки (как оно приходит в поле `Recorder`).
