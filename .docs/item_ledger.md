# Item Ledger

Нормативная модель:

- [`CANON.md`](CANON.md);
- [`reservation-replenishment-core.md`](reservation-replenishment-core.md);
- [`planning-truth-contract.md`](planning-truth-contract.md);
- [`notes/mrp-item-ledger-design.md`](notes/mrp-item-ledger-design.md);
- [`notes/item-ledger-view-contract.md`](notes/item-ledger-view-contract.md).

1С читается pull-by-document в `stock_ledger_entry`. `stock_bin` хранит
материализованный остаток. Balance служит только сверкой и источником
начального якоря, но не плановым остатком.

Одна `ReservationEntry` соответствует одному требованию. Она хранит полный
резерв, покрытие наличием на freeze, зафиксированную потребность пополнения и
адресно-FIFO назначения пополнений. `make` и `buy` выбирают рабочий журнал;
расчёт общий.

Агрегированная строка закупки связывается со всеми исходными резервами через
`PurchaseExportObligationAllocation`; её поступление сначала распределяется
по этим живым резервам в пределах `allocated_qty`, затем FIFO. Возвраты
разматывают прежние назначения newest-first по правилам §15 журнала решений.

Свободный S0 нового плана исключает динамические удержания старших живых
резервов. Удержание освобождает только принятый назначенный расход, но не
поступление.

Физический выпуск готового изделия тем же чистым количеством уменьшает остаток
соответствующей строки общей очереди сборки. Контракт очереди:
[`assembly-queue-and-drum.md`](assembly-queue-and-drum.md).

Тяжёлые операции строят кандидат, проверяют его и атомарно публикуют принятое
поколение. Читатели не пересчитывают данные.

Одно физическое движение может быть записано документом 1С несколькими
строками регистра. Фактом реализации становится только чистое количество
документа `max(sum(assembly_in) - sum(assembly_out), 0)`; внутренние
перемещения того же документа фактом не являются, а физический баланс
остаётся неизменным.

Запрещены legacy stock, повторный расчёт BOM при refresh, двойное назначение
факта, отказ учитывать принятый факт из-за provenance и fallback при
отсутствии Ledger.

Планировщики читают остатки только из принятого поколения Item Ledger.
