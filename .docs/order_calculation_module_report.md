# Модуль расчёта заказов на производство: Детальный отчет

## Обзор

Модуль расчёта заказов на производство представляет собой комплексную систему планирования, предназначенную для автоматического вычисления потребностей в компонентах и формировании заказов на производство и закупку. Модуль включает в себя современные MRP (Material Requirements Planning) функции с поддержкой производственных мощностей, расчётом нормативов, приоритезацией заказов и управлением буферами.

## Архитектура модуля

### Основные компоненты

1. **planning_service.py** - основной сервис, реализующий бизнес-логику планирования
2. **order_quantity_calculator.py** - калькулятор количеств заказов с учётом буферов, оптимальных партий и доступности компонентов
3. **plan_service.py** - сервис для работы с плановыми данными
4. **capacity_scheduler.py** - планировщик загрузки производственных мощностей
5. **pegging_builder.py** - построитель трассировки потребностей (связей компонент-родитель)
6. **priority_manager.py** - менеджер приоритетов заказов

### Структура данных

- **PlannedOrder** - производственные заказы
- **PlannedPurchase** - заказы на закупку
- **PlannedOrderStage** - этапы производственных заказов
- **CapacityLoad** - загрузка мощностей
- **PeggingLink** - связи между компонентами и родительскими изделиями
- **ProductionResource** - производственные ресурсы
- **ProductionKind** - виды производства
- **PlanningRun** - прогоны планирования

## Процесс обработки заказов

### 1. Подготовительный этап

#### Загрузка конфигурации
- Загружается активная конфигурация планирования из `PlanningConfigVersion`
- Применяются возможные переопределения конфигурации
- Устанавливаются параметры планирования: горизонт, политики поставок, настройки лотизации

#### Подготовка исходных данных
- Загрузка MPS (Master Production Schedule) - основного расписания производства
- Загрузка спецификаций (BOM) и операций
- Загрузка остатков на складе и WIP (Work In Progress)
- Загрузка производственных ресурсов и мощностей

### 2. Расчёт валовой потребности (Gross Requirements)

#### BOM-развёртка
- Для каждого изделия из MPS выполняется развёртка BOM
- Рассчитываются потребности в компонентах на основе структуры изделия
- Применяется рекурсивный алгоритм развёртки с ограничением глубины (до 200 уровней)
- Защита от циклических зависимостей

#### Временные горизонты
- Поддержка дневных и недельных (пятница ISO недели) горизонтов
- Автоматическое определение Dcontig - максимального непрерывного дня от начала горизонта
- Всё до Dcontig планируется в дневных горизонтах, после - в недельных

### 3. Расчёт чистой потребности (Net Requirements)

#### Учёт остатков
- Валовая потребность уменьшается на величину текущих остатков
- Учитываются WIP (заказы в производстве) из `production_orders`
- Результирующая чистая потребность = валовая - остатки - WIP

#### Применение коэффициентов безопасности
- К чистой потребности применяется коэффициент безопасности (safety_stock_percent)
- Учитываются настройки политики безопасности

### 4. Классификация потоков

#### Определение типа поставки
- Классификация по методу пополнения: производство или закупка
- Эвристика: если в наименовании метода содержится "покуп", "purchase", "закуп" - это закупка
- В противном случае - производство

### 5. Формирование заказов

#### Заказы на закупку
- Определение сроков поставки на основе времени поставки (lead_time)
- Применение правил лотизации (MOQ, кратность, округление)
- Заказ на закупку = чистая потребность, нормализованная по правилам лотизации

#### Производственные заказы
- Использование `OrderQuantityCalculator` для вычисления количества
- Приоритеты:
  1. Оптимальная партия из карточки номенклатуры (если > буфера)
  2. Буферное количество (среднедневная потребность * дни буфера по участку)
  3. Стандартные правила лотизации (min_batch, multiple, rounding)

#### Ограничения
- Ограничение по доступности компонентов (остатки + WIP)
- Ограничение по горизонту планирования (сумма чистых потребностей)
- Ограничение по производственным мощностям

### 6. Назначение этапов и мощностей

#### Определение этапа производства
- Использование `determine_parent_stage_and_norm` для определения этапа
- Алгоритм анализирует структуру изделия и операции для определения подходящего этапа
- Поддержка специальных правил для покраски (по операциям или по наименованию)

#### Назначение производственного вида
- Использование сопоставления спецификация → вид производства
- Сопоставление вид производства → ресурсы
- Выбор ресурса с максимальной доступной мощностью

#### Назначение мощностей
- Использование `CapacityScheduler` для распределения часов по дням
- Обратное планирование от даты необходимости
- Учёт 5/2 календаря (понедельник-пятница рабочие дни)
- Учёт мощности ресурсов (часы в день * коэффициент мощности)

### 7. Построение трассировки (Pegging)

#### Связи компонент-родитель
- Построение одноразовых связей (one-level) child→parent
- Использование `PeggingBuilder` для создания `PeggingLink`
- Связи создаются по горизонтам потребностей

### 8. Приоритезация заказов

#### Расчёт приоритетов
- Использование `PriorityManager` для вычисления приоритетов
- Веса: критичность (0.4), важность (0.3), цикл времени (0.3)
- Сортировка заказов по приоритету для разрешения конфликтов по мощностям

### 9. Агрегация мощностей

#### Расчёт загрузки
- Агрегация запланированных часов по участкам и дням
- Расчёт доступных часов и перегрузок
- Поддержка дневных и недельных горизонтов

### 10. Финализация прогона

#### Запись результатов
- Закрытие прогона с указанием статуса (SUCCESS/FAILED)
- Сохранение KPI и предупреждений
- Формирование отчетов о дефиците и перегрузках

## Ключевые особенности

### Поддержка буферов
- Буферы участков на основе дней буфера и среднедневной потребности
- Приоритет оптимальной партии над буфером
- Возможность настройки дней буфера для каждого ресурса

### Управление мощностями
- Ограничение количества по доступной мощности
- Обратное планирование с учётом доступности
- Выявление и отслеживание перегрузок

### Гибкие правила лотизации
- Поддержка MOQ, кратности, округления
- Приоритет оптимальной партии
- Разные правила для производства и закупки

### Трассировка потребностей
- Возможность отслеживания связей компонент-родитель
- Помощь в анализе причин дефицита

### Приоритезация заказов
- Многокритериальный расчёт приоритетов
- Учёт критичности, важности и времени цикла
- Приоритеты влияют на распределение мощностей

## Выводы

Модуль расчёта заказов на производство представляет собой современную MRP-систему с широкими возможностями по планированию, управлению мощностями и трассировке потребностей. Архитектура модуля позволяет эффективно рассчитывать потребности в компонентах, формировать заказы на производство и закупку, учитывать ограничения по мощностям и приоритеты заказов. Модуль поддерживает гибкую настройку параметров планирования и обеспечивает прозрачность процесса через систему трассировки и приоритезации.
