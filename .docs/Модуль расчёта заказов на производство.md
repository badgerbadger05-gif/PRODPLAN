# Модуль расчёта заказов на производство

Комплексный модуль планирования производственных заказов, интегрирующий принципы MRP с динамической приоритизацией и календарным планированием мощностей.

## Архитектура модуля

### Входные данные системы

Модуль обрабатывает следующие источники информации:

*   **План выпуска продукции** — календарный график готовых изделий по дням с номенклатурой и количеством.
*   **Технологические нормы** — детали с временными нормативами операций, распределённые по производственным участкам.
*   **Ресурсы участков** — производственные мощности с параметрами времени работы, графиком и коэффициентом мощности (множителем пропускной способности).
*   **Складские остатки** — текущие запасы производимых деталей, полуфабрикатов и материалов.
*   **Иерархическая спецификация (BOM)** — многоуровневая структура состава изделий с коэффициентами входимости компонентов.

## Алгоритм обработки данных

### Этап 1: Разложение производственной программы

Система выполняет рекурсивное развёртывание плана выпуска через иерархическую спецификацию:

1.  **Загрузка MPS** — извлечение главного календарного плана готовых изделий.
2.  **Развёртка по уровням BOM** — последовательный обход дерева спецификации от готовых изделий к компонентам.
3.  **Расчёт валовой потребности** — определение общего количества каждой детали с учётом коэффициентов входимости.
4.  **Агрегирование временных потребностей** — суммирование потребностей в календарном разрезе.

### Этап 2: Обработка множественного использования

Для деталей, входящих в различные изделия, выполняется накопительный расчёт потребностей:

```
Общая_потребность(деталь) = Σ(Количество_изделия × Норма_расхода_детали_на_изделие)
```

Система отслеживает все пути использования компонентов и суммирует потребности от всех родительских изделий.

### Этап 3: Расчёт чистой потребности

Определяется реальная потребность в изготовлении с учётом наличных ресурсов:

```
Чистая_потребность = Валовая_потребность - Остатки_на_складе - Заказы_в_производстве
```

## Система динамической приоритизации

### Этап 4: Анализ критичности дефицита

Система рассчитывает временные горизонты исчерпания запасов для каждой детали:

```
Время_исчерпания = Остаток_на_складе ÷ Среднедневной_расход
Коэффициент_критичности = (Дата_потребности - Текущая_дата) ÷ Время_исчерпания
```

**Классификация приоритетов:**

*   **Критический (< 1.0)** — запасы закончатся раньше даты потребности.
*   **Высокий (1.0-1.2)** — малый запас времени, требует внимания.
*   **Средний (1.2-1.5)** — стабильная ситуация с контролируемым риском.
*   **Низкий (> 1.5)** — достаточный резерв времени.

### Этап 5: Формирование очереди приоритетов

Заказы выстраиваются по комбинированному индексу приоритетности:

```
Индекс_приоритета = (Коэффициент_критичности × 0.4) + 
                   (Важность_заказа × 0.3) + 
                   (Длительность_цикла × 0.3)
```

## Календарное планирование мощностей

### Этап 6: Временное планирование операций

Система рассчитывает календарные сроки изготовления с учётом производственных циклов:

*   **Обратное планирование** — от даты потребности определяется дата начала с учётом длительности цикла.
*   **Расчёт временной нагрузки** — определение трудозатрат по формуле:

```
Время_операции = Количество_деталей × Норма_времени_на_деталь
```

### Этап 7: Распределение по производственным мощностям

Ключевая особенность — учёт коэффициента мощности участков:

*   `Базовая мощность = Время_работы × График_работы`
*   `Эффективная мощность = Базовая_мощность × Коэффициент_мощности`
*   **Проверка загрузки** — сравнение плановой нагрузки с доступной мощностью.
*   **Балансировка ресурсов** — перераспределение при превышении мощностей.

## Оптимизация и управление конфликтами

### Этап 8: Разрешение ресурсных конфликтов

При одновременной потребности в ресурсах применяется иерархия решений:

1.  **Приоритет по критичности** — детали с коэффициентом < 1.0.
2.  **Приоритет по важности заказа** — ключевые клиенты и контракты.
3.  **Приоритет по рентабельности** — заказы с наибольшей маржинальностью.
4.  **Временной приоритет** — FIFO для заказов с идентичными параметрами.

### Этап 9: Автоматические корректировки

Система инициирует корректирующие действия при выявлении проблем:

*   **Увеличение размера партии** — при частом дефиците однотипных деталей.
*   **Сокращение цикла** — через перераспределение мощностей на приоритетные заказы.
*   **Альтернативная маршрутизация** — использование резервных участков и оборудования.
*   **Изменение календаря** — введение сверхурочных для критических заказов.

## Выходные данные модуля

### Этап 10: Генерация производственных заданий

Система формирует комплексный план производства:

*   **Календарный план изготовления** — детали по участкам и временным периодам.
*   **Производственные заказы** — с номенклатурой, количеством, сроками и приоритетами.
*   **Загрузка мощностей** — детализация по участкам и временным интервалам.
*   **Критические ресурсы** — узкие места и ограничивающие факторы.
*   **Планы закупок** — для компонентов, требующих внешних поставок.

## Контрольные показатели эффективности

Модуль генерирует KPI для мониторинга качества планирования:

*   **Процент заказов в срок** — доля выполненных без задержек заказов.
*   **Средний уровень запасов** — оптимизация складских остатков.
*   **Коэффициент загрузки мощностей** — равномерность распределения нагрузки.
*   **Время реакции на дефицит** — скорость выявления и устранения нехваток.
*   **Эффективность приоритизации** — соответствие фактических сроков плановым.

Интегрированный подход модуля обеспечивает проактивное управление производством с минимизацией рисков дефицита, оптимальным использованием ресурсов и максимизацией выполнения плановых показателей.

## Полная логика системы планирования производства с учетом всех компонентов

### Базовая MRP-логика (существующая)
Система основана на классических принципах планирования материальных потребностей, где основными входными данными служат:

- План выпуска продукции с календарными датами
- Иерархическая спецификация изделий с многоуровневой структурой состава
- Текущие складские остатки компонентов
- Технологические нормы времени операций
- Производственные мощности участков с коэффициентами загрузки

Базовый алгоритм выполняет рекурсивное развёртывание производственной программы через спецификации для определения валовой потребности, обрабатывает множественное использование компонентов путём суммирования потребностей, рассчитывает чистую потребность вычитанием остатков из валовой потребности, классифицирует заказы по приоритетам на основе коэффициента критичности и выполняет временное планирование с обратным отсчётом от даты потребности.

### Модифицированная логика с новыми компонентами

#### 1. Расчёт базового количества через буферные дни участков
Для каждой детали система определяет минимальное количество к запуску исходя из буферных дней, установленных индивидуально для каждого производственного участка. Количество рассчитывается как сумма ежедневных потребностей в детали на период, равный количеству буферных дней участка. Например, если участок имеет буфер 5 дней, а ежедневная потребность составляет 10 деталей, то базовое количество составит 50 штук.

#### 2. Применение приоритета оптимальных партий запуска
Система проверяет наличие индивидуально установленной оптимальной партии для каждой детали. Если оптимальная партия определена и превышает буферное количество, она становится базой для расчёта. Если оптимальная партия меньше буферного количества, система использует кратные оптимальной партии величины для покрытия буферной потребности. При отсутствии оптимальной партии используется количество, рассчитанное по буферным дням.

#### 3. Ограничение по доступности комплектующих
Система анализирует иерархию спецификаций и проверяет наличие всех необходимых компонентов для производства расчётного количества родительской детали. Для каждого компонента рассчитывается общая потребность с учётом норм расхода, определяется доступное количество как сумма остатков, незавершённого производства и заказов на закупку. Финальное количество к производству ограничивается наиболее дефицитным компонентом.

#### 4. Ограничение по горизонту планирования
Система рассчитывает совокупную потребность в детали на установленном плановом горизонте, учитывая как прямую потребность из основного плана, так и зависимую потребность через родительские изделия. Максимальное количество к производству не может превышать общую потребность на горизонте планирования за вычетом уже имеющихся остатков и заказов в работе. Это предотвращает затоваривание и образование избыточных запасов.

#### 5. Определение критичности и срочности
Когда система обнаруживает, что родительское изделие не может быть произведено в требуемом количестве из-за недостатка компонентов, она автоматически повышает приоритет недостающих деталей. Уровень срочности рассчитывается исходя из соотношения дефицита к общей потребности и времени до требуемой даты поставки. Система классифицирует срочность как критическую, высокую, среднюю или низкую.

### Интегрированный алгоритм принятия решений
Система последовательно применяет все ограничения, выбирая наиболее лимитирующий фактор:

- Этап 1: Расчёт буферного количества на основе дней покрытия участка
- Этап 2: Корректировка на оптимальную партию запуска (если установлена)
- Этап 3: Ограничение максимальной потребностью на горизонте планирования
- Этап 4: Проверка доступности всех необходимых комплектующих
- Этап 5: Финальное определение количества как минимума из всех ограничений

### Система мониторинга и визуализации
Система ведёт учёт лимитирующих факторов для каждого заказа, создаёт алерты по критичным недостачам компонентов с указанием рекомендуемых действий (срочная закупка, изменение приоритетов производства, сверхурочная работа). Визуализация включает цветовую индикацию уровней срочности, тепловые карты недостач компонентов по времени и дашборды потенциальных избытков для предотвращения затоваривания.

### Результат применения логики
Модифицированная система обеспечивает оптимальное планирование производства, автоматически балансируя между необходимостью поддержания бесперебойной работы через буферы, экономической эффективностью через оптимальные партии, физическими ограничениями по комплектующим и предотвращением избыточных запасов через горизонт планирования. Система автоматически выявляет и приоритизирует критичные ситуации, предоставляя менеджерам инструменты для оперативного принятия решений по корректировке планов производства и закупок.

## Планируемые улучшения и изменения

В рамках дальнейшего развития системы планируется модернизация модуля расчёта заказов на производство. В текущей реализации недостаточно гибко учитывается необходимость буферных запасов и оптимальных размеров партий, что снижает эффективность планирования при высокой вариативности спроса и длительных циклах производства.

### Изменения в пользовательском интерфейсе

1. **Настройка буфера на странице "Производственные ресурсы"**:
   - В окне ввода параметров ресурса изменить название поля с текущего на "Буфер (дней)"
   - Значение, вводимое в это поле, будет использоваться как величина буфера в днях при расчёте потребностей
   - Это позволит учитывать дополнительный запас времени для компенсации вариаций в сроках поставки и производства

2. **Оптимальный размер партии**:
   - В качестве дополнительного атрибута номенклатуры добавить поле "Оптимальная партия"
   - На странице "Распределение этапов" предусмотреть дополнительную редактируемую колонку для ввода этого параметра
   - При расчёте заказов учитывать этот параметр как целевой размер партии для минимизации издержек на переналадку и хранение

Эти изменения позволят повысить точность расчётов и адаптивность системы планирования к реальным условиям производства.
