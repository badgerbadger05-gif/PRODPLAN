# PRODPLAN: Настройка и администрирование

**Версия:** 2.0  
**Дата:** 2025-09-24

## 🔧 Управление сервисами

Вся система PRODPLAN управляется через Docker Compose. Основные команды выполняются в корневой директории проекта.

### Запуск и остановка

- **Запустить все сервисы в фоновом режиме:**
  ```bash
  docker-compose up -d
  ```

- **Остановить все сервисы:**
  ```bash
  docker-compose down
  ```

### Просмотр логов

Вы можете просматривать логи для каждого сервиса в реальном времени.

- **Просмотр логов всех сервисов:**
  ```bash
  docker-compose logs -f
  ```

- **Просмотр логов конкретного сервиса (например, backend):**
  ```bash
  docker-compose logs -f backend
  ```

### Пересборка образов

Если вы внесли изменения в код (например, в `backend/` или `frontend/`), вам нужно пересобрать Docker-образы.

- **Для Windows (рекомендуемый способ):**
  ```cmd
  rebuild.bat
  ```

- **Вручную:**
  ```bash
  docker-compose build --no-cache
  docker-compose up -d
  ```

## 🗄️ Управление базой данных (PostgreSQL)

База данных PostgreSQL работает в отдельном Docker-контейнере (`db`).

### Подключение к базе данных

Вы можете подключиться к базе данных с помощью любого клиента PostgreSQL (например, DBeaver, pgAdmin), используя следующие параметры:

- **Хост**: `localhost`
- **Порт**: `5432`
- **База данных**: `prodplan`
- **Пользователь**: `prodplan`
- **Пароль**: `password`

(Эти значения определены в файле `docker-compose.yml`)

### Резервное копирование (Бэкап)

Данные PostgreSQL хранятся в Docker-volume с именем `prodplan_postgres_data`. Для создания бэкапа рекомендуется использовать стандартную утилиту `pg_dump`.

1.  **Убедитесь, что контейнеры запущены.**
2.  **Выполните команду:**

    ```bash
    docker-compose exec -T db pg_dump -U prodplan -d prodplan > backup.sql
    ```

    Эта команда создаст файл `backup.sql` в корневой директории проекта.

### Восстановление из бэкапа

1.  **Убедитесь, что контейнеры запущены.**
2.  **Скопируйте SQL-дамп в контейнер и выполните его:**

    ```bash
    cat backup.sql | docker-compose exec -T db psql -U prodplan -d prodplan
    ```

## 🔐 Интеграция с 1С

Настройки для подключения к OData API 1С передаются в Backend-сервис через запросы на эндпоинты синхронизации. Конфигурация выполняется на странице "Синхронизация" в веб-интерфейсе.

### Тестирование OData подключения

Для проверки доступности OData-сервиса 1С изнутри Docker-контейнера, можно выполнить команду:

```bash
docker-compose exec backend curl -u "username:password" "http://your-1c-server/odata/standard.odata/\$metadata"
```

**Важно:** Если ваш сервер 1С находится в той же локальной сети, что и Docker, может потребоваться настроить `extra_hosts` в `docker-compose.yml`, чтобы контейнер `backend` мог найти сервер по его имени.

Пример (уже есть в `docker-compose.yml`):
```yaml
extra_hosts:
  - "mtzw7:10.36.0.6"
  - "mtzw7.lan:10.36.0.6"
```
