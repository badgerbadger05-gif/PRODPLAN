# Модуль расчёта заказов на производство

Комплексный модуль планирования производственных заказов, интегрирующий принципы MRP с динамической приоритизацией и календарным планированием мощностей.

## Архитектура модуля

### Входные данные системы

Модуль обрабатывает следующие источники информации:

*   **План выпуска продукции** — календарный график готовых изделий по дням с номенклатурой и количеством.
*   **Технологические нормы** — детали с временными нормативами операций, распределённые по производственным участкам.
*   **Ресурсы участков** — производственные мощности с параметрами времени работы, графиком и коэффициентом мощности (множителем пропускной способности).
*   **Складские остатки** — текущие запасы производимых деталей, полуфабрикатов и материалов.
*   **Иерархическая спецификация (BOM)** — многоуровневая структура состава изделий с коэффициентами входимости компонентов.

## Алгоритм обработки данных

### Этап 1: Разложение производственной программы

Система выполняет рекурсивное развёртывание плана выпуска через иерархическую спецификацию:

1.  **Загрузка MPS** — извлечение главного календарного плана готовых изделий.
2.  **Развёртка по уровням BOM** — последовательный обход дерева спецификации от готовых изделий к компонентам.
3.  **Расчёт валовой потребности** — определение общего количества каждой детали с учётом коэффициентов входимости.
4.  **Агрегирование временных потребностей** — суммирование потребностей в календарном разрезе.

### Этап 2: Обработка множественного использования

Для деталей, входящих в различные изделия, выполняется накопительный расчёт потребностей:

```
Общая_потребность(деталь) = Σ(Количество_изделия × Норма_расхода_детали_на_изделие)
```

Система отслеживает все пути использования компонентов и суммирует потребности от всех родительских изделий.

### Этап 3: Расчёт чистой потребности

Определяется реальная потребность в изготовлении с учётом наличных ресурсов:

```
Чистая_потребность = Валовая_потребность - Остатки_на_складе - Заказы_в_производстве
```

## Система динамической приоритизации

### Этап 4: Анализ критичности дефицита

Система рассчитывает временные горизонты исчерпания запасов для каждой детали:

```
Время_исчерпания = Остаток_на_складе ÷ Среднедневной_расход
Коэффициент_критичности = (Дата_потребности - Текущая_дата) ÷ Время_исчерпания
```

**Классификация приоритетов:**

*   **Критический (< 1.0)** — запасы закончатся раньше даты потребности.
*   **Высокий (1.0-1.2)** — малый запас времени, требует внимания.
*   **Средний (1.2-1.5)** — стабильная ситуация с контролируемым риском.
*   **Низкий (> 1.5)** — достаточный резерв времени.

### Этап 5: Формирование очереди приоритетов

Заказы выстраиваются по комбинированному индексу приоритетности:

```
Индекс_приоритета = (Коэффициент_критичности × 0.4) + 
                   (Важность_заказа × 0.3) + 
                   (Длительность_цикла × 0.3)
```

## Календарное планирование мощностей

### Этап 6: Временное планирование операций

Система рассчитывает календарные сроки изготовления с учётом производственных циклов:

*   **Обратное планирование** — от даты потребности определяется дата начала с учётом длительности цикла.
*   **Расчёт временной нагрузки** — определение трудозатрат по формуле:

```
Время_операции = Количество_деталей × Норма_времени_на_деталь
```

### Этап 7: Распределение по производственным мощностям

Ключевая особенность — учёт коэффициента мощности участков:

*   `Базовая мощность = Время_работы × График_работы`
*   `Эффективная мощность = Базовая_мощность × Коэффициент_мощности`
*   **Проверка загрузки** — сравнение плановой нагрузки с доступной мощностью.
*   **Балансировка ресурсов** — перераспределение при превышении мощностей.

## Оптимизация и управление конфликтами

### Этап 8: Разрешение ресурсных конфликтов

При одновременной потребности в ресурсах применяется иерархия решений:

1.  **Приоритет по критичности** — детали с коэффициентом < 1.0.
2.  **Приоритет по важности заказа** — ключевые клиенты и контракты.
3.  **Приоритет по рентабельности** — заказы с наибольшей маржинальностью.
4.  **Временной приоритет** — FIFO для заказов с идентичными параметрами.

### Этап 9: Автоматические корректировки

Система инициирует корректирующие действия при выявлении проблем:

*   **Увеличение размера партии** — при частом дефиците однотипных деталей.
*   **Сокращение цикла** — через перераспределение мощностей на приоритетные заказы.
*   **Альтернативная маршрутизация** — использование резервных участков и оборудования.
*   **Изменение календаря** — введение сверхурочных для критических заказов.

## Выходные данные модуля

### Этап 10: Генерация производственных заданий

Система формирует комплексный план производства:

*   **Календарный план изготовления** — детали по участкам и временным периодам.
*   **Производственные заказы** — с номенклатурой, количеством, сроками и приоритетами.
*   **Загрузка мощностей** — детализация по участкам и временным интервалам.
*   **Критические ресурсы** — узкие места и ограничивающие факторы.
*   **Планы закупок** — для компонентов, требующих внешних поставок.

## Контрольные показатели эффективности

Модуль генерирует KPI для мониторинга качества планирования:

*   **Процент заказов в срок** — доля выполненных без задержек заказов.
*   **Средний уровень запасов** — оптимизация складских остатков.
*   **Коэффициент загрузки мощностей** — равномерность распределения нагрузки.
*   **Время реакции на дефицит** — скорость выявления и устранения нехваток.
*   **Эффективность приоритизации** — соответствие фактических сроков плановым.

Интегрированный подход модуля обеспечивает проактивное управление производством с минимизацией рисков дефицита, оптимальным использованием ресурсов и максимизацией выполнения плановых показателей.
