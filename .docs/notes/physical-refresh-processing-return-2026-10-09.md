# Возврат от переработчика блокировал physical refresh

09.10.2026 подтверждён повторный отказ обновления после accepted g1905
(cutoff 08.10 11:16:57 МСК). Ошибка относилась к SLE 263703: 14 шт.
VP-000405, документ ЗСНФ-001805 от 27.08.2026. Чтение 1С подтвердило
`Posted=true`, `ВидОперации=ВозвратОтПереработчика`, ключ операции
`8d96f3f0-9934-11eb-e39a-fa163e61326a`. Событие никогда не имело supplier
provenance. Его отсутствие останавливало полный signed stream затронутого
BUY scope, публикацию нового Ledger и команды подготовки комплектующих.

Это физическое поступление после переработки, а не закупка. Классификация
принадлежит существующему `supplier_receipt_odata.py`: должны одновременно
совпасть тип документа, ключ и имя операции. Неизвестная операция остаётся
ошибкой. Сохранённое исключение имеет `match_status=excluded_non_supplier`
и `operation_kind=non_supplier_receipt`; supplier-order ref/line отсутствуют.
В physical StockBin движение входит, а в ReceiptFact/BUY FIFO не входит.

Миграция `20261009_01` расширяет только два CHECK ограничения provenance.
Количество физических фактов и frozen-обязательства не переписываются.
Downgrade запрещён, пока существует новое типизированное исключение.

Для старого принятого события требуется явная ограниченная maintenance-фаза:

```text
python tools/diagnostics/non_supplier_receipt_repair.py --expected-generation-id 1905 --sle-ids 263703
python tools/diagnostics/non_supplier_receipt_repair.py --expected-generation-id 1905 --sle-ids 263703 --apply
```

По умолчанию выполняется dry-run. Apply сериализуется cluster/lifecycle
locks и требует отсутствия активного physical candidate. Указатель должен
совпадать с ожидаемым. Источники должны быть видимы в принятой физике и
выбранном складском контуре. Новая типизация берётся только из канонического
чтения документов 1С. Существующая supplier-типизация, неизвестная прежняя
типизация или текущее назначение количества блокируют ремонт. Повтор — no-op.
Инструмент не проводит документы 1С, не добавляет stock и не назначает FIFO.

Приёмка: принять новый physical Ledger; убедиться, что SLE 263703 имеет
исключение и не имеет BUY-назначения, новые обычные поставки учитываются;
проверить подготовку 30 шт. для MRP-R-513460 и комплектующие MRP-R-518519,
а также успешный следующий автоматический цикл обновления.

Отдельная проверка: списание ЗСНФ-000602 от 08.10 16:13:17 на момент чтения
09.10 было `Posted=false`, физических SLE не имело. Сохранённый документ
не является фактом расхода до проведения оператором и принятого read-back.
