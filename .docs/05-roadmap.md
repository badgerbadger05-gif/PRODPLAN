# PRODPLAN: План развития и backlog

**Версия:** 2.0  
**Дата:** 2025-09-24

## 🎯 Текущий статус системы

### ✅ Реализовано (v2.0)
- **Архитектура**: Миграция на Docker-контейнеры с PostgreSQL, FastAPI (backend) и Quasar (frontend) завершена.
- **Backend**: 
  - Реализованы API-эндпоинты для синхронизации данных из 1С (`/api/v1/sync/*`).
  - Реализованы API для получения дерева спецификаций (`/api/v1/specification/*`), включая полную рекурсивную развертку.
  - Настроено подключение к PostgreSQL через SQLAlchemy.
- **Frontend**:
  - Созданы основные страницы: "План", "Спецификация", "Синхронизация", "Настройки".
  - Реализован компонент для отображения иерархической спецификации (дерево).
  - Настроено взаимодействие с backend API.
- **Инфраструктура**:
  - Проект полностью управляется через `docker-compose.yml`.
  - Имеются скрипты для легкого запуска (`start.bat`, `start.sh`) и пересборки (`rebuild.bat`).

## 🚧 Backlog по приоритетам

### 🔴 P1 — Критичные задачи

#### Валидация данных на стороне Backend
**Проблема**: Недостаточная валидация данных, поступающих от 1С и от клиента.
**Решение**:
- Добавить Pydantic-схемы с более строгими правилами.
- В сервисах (`backend/app/services/`) реализовать проверки на консистентность данных (например, проверку циклических ссылок в спецификациях, проверку наличия обязательных полей).
**Оценка**: 3 дня

#### Unit и интеграционные тесты для Backend
**Проблема**: Отсутствие тестов, что замедляет разработку и повышает риск регрессий.
**Решение**:
- Настроить `pytest`.
- Написать тесты для ключевых сервисов: `specification_sync`, `plan_service`, `stages_calculator`.
- Покрыть тестами API-эндпоинты в `backend/app/routers/`.
**Оценка**: 8 дней

#### Улучшение обработки ошибок на Frontend
**Проблема**: Ошибки API не всегда понятно отображаются для пользователя.
**Решение**:
- Создать централизованный обработчик ошибок в `frontend/src/services/api.ts`.
- Использовать компоненты Quasar (например, `QNotify`) для отображения сообщений об ошибках.
**Оценка**: 2 дня

### 🟡 P2 — Важные улучшения

#### Логирование операций в Backend
**Проблема**: Логирование не стандартизировано.
**Решение**:
- Настроить `logging` в `backend/app/main.py` для вывода структурированных логов.
- Добавить информативные логи в ключевые сервисы и роутеры для отслеживания потока выполнения запросов.
**Оценка**: 3 дня

#### Расширение функционала страницы "План"
**Проблема**: Текущая страница плана имеет базовый функционал.
**Решение**:
- В `frontend/src/pages/PlanPage.vue` добавить фильтры, сортировку.
- Реализовать сохранение изменений плана в реальном времени или по кнопке.
- Добавить экспорт плана в Excel с помощью внешней библиотеки.
**Оценка**: 6 дней

#### Конфигурация через переменные окружения
**Проблема**: Некоторые настройки (например, URL OData) передаются в теле запроса.
**Решение**:
- Перенести конфигурацию (адреса, креды по умолчанию) в переменные окружения, которые читаются в `backend/app/main.py` и используются сервисами.
**Оценка**: 2 дня

## 🔄 Технический долг

### Рефакторинг кода
- **Backend**: Выделить общую логику из роутеров в сервисы. Улучшить типизацию с помощью `Pydantic` и `SQLAlchemy`.
- **Frontend**: Вынести переиспользуемую логику из Vue-компонентов в Pinia stores (`frontend/src/stores/`). Компоненты должны отвечать только за отображение.

### Производительность
- **Backend**: Оптимизировать сложные SQL-запросы в `SQLAlchemy`, добавить необходимые индексы в модели (`backend/app/models.py`).
- **Frontend**: Использовать виртуальную прокрутку (`QVirtualScroll`) для больших списков и деревьев, чтобы избежать проблем с производительностью рендеринга.
