# PRODPLAN: Интеграция с ИИ (Семантический поиск)

**Версия:** 1.0
**Дата:** 2025-11-28

## 🧠 Обзор

PRODPLAN использует технологии искусственного интеллекта для улучшения пользовательского опыта, в частности, для реализации **семантического (смыслового) поиска** по справочнику номенклатуры. Это позволяет находить товары не по точному совпадению, а по смысловой близости запроса.

## ⚙️ Как это работает

Механизм семантического поиска состоит из двух основных этапов:

1.  **Генерация эмбеддингов**: Для каждой номенклатурной позиции создается текстовое описание (имя, артикул, код), которое затем преобразуется в числовой вектор (эмбеддинг) с помощью нейросетевой модели.
2.  **Поиск по схожести**: Когда пользователь вводит поисковый запрос, он также преобразуется в вектор. Затем система вычисляет **косинусное сходство** между вектором запроса и векторами всех номенклатурных позиций в базе данных, возвращая наиболее близкие результаты.

### Архитектура компонента

```
┌───────────────────┐   1. Генерация   ┌────────────────────┐   2. Сохранение   ┌───────────────────┐
│  Номенклатура     │─────────────────▶│   Embedding Model  │────────────────▶│  База данных      │
│ (имя, артикул...) │   (текст)        │ (all-MiniLM-L6-v2) │   (вектор)      │ (таблица          │
└───────────────────┘                  └────────────────────┘                 │ ItemEmbedding)    │
                                                                            └───────────────────┘
        ▲
        │ 3. Поиск
        │
┌───────────────────┐
│  Пользовательский │
│  запрос (текст)   │
└───────────────────┘
```

## 🛠️ Реализация

### Хранение эмбеддингов

-   Векторные представления хранятся в таблице `item_embeddings`, которая связана с основной таблицей номенклатуры `items`.
-   Каждая запись содержит `item_id`, сам вектор (`embedding_vector`) и название модели, которая его сгенерировала.
-   **Модель по умолчанию**: `sentence-transformers/all-MiniLM-L6-v2`.

Ссылка на схему: **[Схема базы данных (db_schema.md)](db_schema.md)** (см. таблицу `item_embeddings`).

### Сервис семантического поиска

-   Вся логика инкапсулирована в сервисе `NomenclatureSearchService` ([`backend/app/services/nomenclature_search.py`](backend/app/services/nomenclature_search.py:12)).
-   Метод `search_nomenclature` является основной точкой входа, которая пытается выполнить семантический поиск и, в случае неудачи, переключается на стандартный текстовый поиск (fallback).
-   Метод `generate_embeddings_for_all_items` позволяет массово сгенерировать и сохранить эмбеддинги для всех активных позиций номенклатуры.

### ⚠️ Текущий статус реализации

На данный момент функция генерации эмбеддингов (`_generate_embedding`) в `nomenclature_search.py` **является заглушкой**. Вместо обращения к реальной нейросетевой модели она генерирует детерминированный псевдо-вектор на основе MD5-хеша от текстового описания.

**Это означает, что семантический поиск реализован на уровне архитектуры, но фактическая смысловая близость пока не вычисляется.** Данный функционал находится на стадии разработки и готов к интеграции с полноценной моделью.

## 🚀 Планы по развитию

1.  **Интеграция с реальной моделью**: Заменить текущую заглушку на вызов `sentence-transformers` или аналогичной библиотеки для генерации качественных эмбеддингов.
2.  **Оптимизация поиска**: Для больших объемов данных рассмотреть использование специализированных векторных баз данных (например, `pgvector` для PostgreSQL, `FAISS`, `Milvus`) для ускорения поиска по схожести.
3.  **Расширение применения**: Использовать эмбеддинги не только для поиска, но и для других задач:
    -   Автоматическая классификация номенклатуры.
    -   Поиск аналогов и замен.
    -   Выявление дубликатов.
