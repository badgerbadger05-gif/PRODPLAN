# Решения по задаче: «Отчёт о выпуске техники (недельный вид + дневное закрытие)»

Дата: 2026-02-06

## 1) Контекст и проблема

Проблема: когда план по изготовлению корневого изделия не выполнен в срок, при автоматическом ежедневном «сдвиге плана» потребность в MRP может «исчезать» (план уезжает, а по факту выпуск не произошёл).

Цель: ввести механизм **фиксации факта выпуска** и **управляемого (не автоматического) переноса остатков**, чтобы план **не сдвигался**, пока не зафиксирован факт.

Текущее состояние проекта:

- Есть страница «План выпуска техники дневной» ([`PlanPage.vue`](frontend/src/pages/PlanPage.vue:1)), работающая как матрица «изделия × даты».
- План хранится в таблице [`ProductionPlanEntry`](backend/app/models.py:293) и читается через `/v1/plan/matrix` ([`get_plan_matrix()`](backend/app/routers/plan.py:119)) → [`query_plan_matrix_paginated()`](backend/app/services/plan_service.py:21).

## 2) Принятые решения (по заполненным ответам)

### 2.1. Календарь рабочих/нерабочих дней

Решение (Q1): **рабочие дни задаются календарём** (праздники/переносы) + базово Сб/Вс нерабочие.

Следствие:

- В недельном отчёте **показываем Пн–Вс**, включая Сб/Вс.
- **Закрытие дня** и **перенос остатков** выполняются только по **рабочим дням**.

### 2.2. Какой день закрываем

Решение (Q2): закрываем строго **предыдущий рабочий день** относительно текущей даты.

То есть, в любой момент есть целевой «день закрытия» `D_close = previous_workday(today)`.

Если несколько рабочих дней были пропущены, применяется правило (Q9): **нельзя закрывать “сегодня”**, пока не закрыты все предыдущие рабочие дни подряд.

### 2.3. Что переносим при закрытии дня

Решение (Q3): переносим остаток **по каждому изделию**:

`carry_qty = max(plan_qty(D_close) - fact_qty(D_close), 0)`.

Перевыпуск не порождает отрицательных переносов.

### 2.4. Куда переносим остаток (важное уточнение)

Решение (Q4) формулировкой примера:

> Если сегодня вторник, а мы закрываем понедельник, то перенос идёт на четверг.

Из этого следует правило:

- перенос выполняется **на рабочий день “через один” после “сегодня”** (условно «послезавтра», с учётом календаря),
- а не на следующий день после закрываемого дня.

Термины:

- `D_close = previous_workday(today)` — день, который закрываем;
- `D_target = next_workday(next_workday(today))` — день, куда переносим остаток.

Выходные при этом **пропускаются** календарём.

### 2.5. Как мерджим перенос с планом целевого дня

Решение (Q5): перенос **добавляется** в план целевого дня:

`plan_qty(D_target) += carry_qty`.

### 2.6. Перевыпуск

Решение (Q6): **перевыпуск разрешён** (факт > план дня).

Поведение:

- перенос по изделию = 0;
- перевыпуск должен быть **отдельно отображён** в UI (например, маркер/подсветка).

### 2.7. Редактирование после закрытия дня

Решение (Q7): после «Закрыть день» факт становится **read-only**.

### 2.8. Повторное закрытие (идемпотентность)

Решение (Q8): повторное «Закрыть день» разрешено как **re-run**:

- откатываем перенос, сделанный прошлым закрытием;
- пересчитываем заново по текущим данным;
- снова применяем перенос.

## 3) Операционная схема процесса (как это работает ежедневно)

1) Пользователь открывает отчёт и заполняет факт за `D_close` (предыдущий рабочий день).
2) Нажимает **«Закрыть день»**.
3) Система в транзакции:
   - фиксирует факт за `D_close` (после чего он read-only),
   - считает `carry_qty` по каждому изделию,
   - находит `D_target = next_workday(next_workday(today))`,
   - применяет перенос `plan_qty(D_target) += carry_qty`,
   - фиксирует, что день закрыт (с возможностью re-run).
4) После этого можно «сдвигать»/продвигать плановое окно (и/или запускать следующие процедуры).

## 4) Термины (для однозначности)

- **План дня** — сколько должно быть выпущено по изделию в конкретную дату.
- **Факт дня** — сколько реально выпущено (вводится вручную).
- **Остаток дня** — `ПланДня - ФактДня`.
- **Перенос** — `max(ОстатокДня, 0)`.
- **Закрытие дня** — подтверждение факта + перенос + разрешение продвижения планового окна.

## 5) Примечания по реализации (для инженера)

- В плане сейчас используется `DateTime` ([`ProductionPlanEntry.date`](backend/app/models.py:293)); для дневных операций важно нормализовать даты (TZ, «начало дня»), иначе возможны пропуски в интервалах.
- Операции «закрыть день» должны быть транзакционными и иметь состояние закрытия по `D_close` (для read-only и корректного re-run).
- Поскольку перенос мерджится через `+=` (см. раздел 2.5), re-run обязательно должен уметь **откатывать** предыдущее применение переноса, иначе будет удвоение.
