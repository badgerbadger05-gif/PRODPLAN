# Изменения в системе фильтрации по датам

## Обзор

В системе планирования производства были внесены фундаментальные изменения в логику фильтрации данных. Эти изменения направлены на улучшение пользовательского опыта, упрощение архитектуры и повышение производительности системы.

## Основные изменения

### 1. Замена фильтрации с `bucket_date` на `start_date`

#### Проблема предыдущей реализации
- Использование `bucket_date` (дата бакета) для фильтрации создавало путаницу для пользователей
- Бакеты могли быть дневными или недельными (пятница ISO недели), что усложняло понимание
- Несоответствие между датой бакета и фактической датой начала производства

#### Новое решение
- Все эндпоинты фильтрации теперь используют `start_date` (дата начала заказа)
- Пользователи фильтруют по фактическим датам начала производства
- Упрощена логика работы с датами

#### Затронутые эндпоинты:
- `GET /api/v1/plan/results/{run_id}/production` - детальные данные производства
- `GET /api/v1/plan/results/{run_id}/production/grouped` - группированные данные
- `GET /api/v1/plan/results/{run_id}/production/export` - экспорт данных

### 2. Удаление функциональности `day_date`

#### Причины удаления
- Функциональность "Задание на день" была избыточной
- Дублировала возможности фильтрации по диапазону дат
- Усложняла архитектуру системы
- Создавала дополнительные точки отказа

#### Удаленные компоненты:
- Эндпоинт `GET /api/v1/plan/results/{run_id}/production/agenda_day`
- Функция `get_run_production_agenda_day` в бэкенде
- Вся связанная логика обработки "дневных заданий"

### 3. Добавление календарей к полям фильтрации

#### Улучшение пользовательского интерфейса
- Добавлены всплывающие календари к полям `date_from` и `date_to`
- Русская локализация интерфейса календарей
- Удобный выбор дат без необходимости ручного ввода

#### Русская локализация:
- **Дни недели**: Воскресенье, Понедельник, Вторник, Среда, Четверг, Пятница, Суббота
- **Короткие дни**: Вс, Пн, Вт, Ср, Чт, Пт, Сб
- **Месяцы**: Январь, Февраль, Март, Апрель, Май, Июнь, Июль, Август, Сентябрь, Октябрь, Ноябрь, Декабрь
- **Короткие месяцы**: Янв, Фев, Мар, Апр, Май, Июн, Июл, Авг, Сен, Окт, Ноя, Дек
- **Первый день недели**: Понедельник

### 4. Агрегация дублирующихся строк

#### Оптимизация производительности
- Улучшена логика агрегации данных на сервере
- Суммирование количеств и нормативов для дублирующихся позиций
- Снижение нагрузки на клиентскую часть

#### Преимущества:
- Более быстрая загрузка данных
- Уменьшение объема передаваемых данных
- Упрощение логики на фронтенде

#### Файл: `backend/app/routers/plan.py`

- Удаление эндпоинта `/results/{run_id}/production/agenda_day`
- Обновление импортов и зависимостей

- Добавление календарей с русской локализацией
- Удаление функциональности выбора дня (`day_date`)

## Преимущества новых изменений

### 1. Упрощение архитектуры
- Удаление избыточных компонентов
- Упрощение логики фильтрации
- Снижение сложности поддержки

### 2. Улучшение пользовательского опыта
- Интуитивно понятная фильтрация по датам начала
- Удобные календари для выбора дат
- Единообразное поведение системы

### 3. Повышение производительности
- Снижение нагрузки на сервер
- Уменьшение объема передаваемых данных
- Оптимизация запросов к базе данных

### 4. Улучшение сопровождаемости
- Чистый и понятный код
- Упрощенная логика фильтрации
- Легкость внесения будущих изменений

## Обратная совместимость

Изменения сохраняют обратную совместимость API:
- Существующие интеграции продолжают работать
- Параметры переименованы, но логика сохраняется
- Нет ломающих изменений в структуре ответов

## Рекомендации по использованию

### Для пользователей:
- Используйте `date_from` и `date_to` для фильтрации по диапазону дат начала
- Воспользуйтесь календарями для удобного выбора дат
- Обращайте внимание на формат дат: YYYY-MM-DD

### Для разработчиков:
- Все новые интеграции должны использовать `start_date` вместо `bucket_date`
- Функциональность "Задание на день" больше не поддерживается
- Для получения дневных данных используйте фильтрацию по конкретной дате в `date_from` и `date_to`

## Заключение

Внесенные изменения значительно улучшают систему фильтрации данных планирования производства. Новая логика более интуитивна для пользователей, проще в поддержке для разработчиков и эффективнее с точки зрения производительности. Система стала более предсказуемой и удобной в использовании.
