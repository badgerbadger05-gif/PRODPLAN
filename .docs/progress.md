# Текущее состояние

Целевая модель утверждена владельцем:

- две ленты номенклатуры: количество и резервы;
- один расчёт потребности пополнения;
- один адресно-FIFO алгоритм физических пополнений;
- `make/buy` как маршрутизация в два журнала;
- одна очередь остатка выпуска всех живых планов;
- барабан как подвижная календарная раскладка этой очереди.

Реализованы единственный принятый Planning Truth, один `FIXED_SNAPSHOT` на
план, каноническое закрытие плана, replenishment-core резерва, назначение
принятых физических выпусков строкам плана и сохранённая общая очередь
сборки. Канонический барабан сохраняется как нормализованные queue/slot/gap
строки. Полки сохраняют target/transfer/pull из замороженных норм, физических
остатков и плиток барабана. Обе проекции входят в публикацию поколения и
читаются без пересчёта. Ручные
DBR-программы, график по `program_id`, feeder/cockpit и их frontend удалены.

Единая рабочая проекция пополнения реализована таблицей
`replenishment_work_item`: одна строка `make/buy` на активный резерв,
публикуемая атомарно вместе с поколением.

Неизменяемый снимок закрытого плана реализован таблицей
`closed_plan_snapshot`; close сохраняет execution payload до удаления
обязательства из живого поколения, а повторное закрытие проверяет
идентичность снимка.

До переделки кода документация из списка `.docs/README.md` является
обязательным контрактом реализации.

Агрегированная колонка `items.stock_qty` удалена из модели, API и активных
читателей. Физический остаток принадлежит только принятому Item Ledger.
