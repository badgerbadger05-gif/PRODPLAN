# Анализ OData-запросов для учёта активных заказов

## Результаты для заказа ЗСНФ-000070

### Заголовок заказа
- Запрос: `GET /Document_ЗаказНаПроизводство?$format=json&$select=Ref_Key,Number,Date,Posted,DeletionMark&$filter=Number eq 'ЗСНФ-000070'`
- Заказ найден, опубликован (Posted: True), не удален (DeletionMark: False)

### Состояние заказа
- GUID состояния: ad2c9f3a-991b-11eb-e39a-fa163e61326a

### Позиции продукции
- Запрос: `GET /Document_ЗаказНаПроизводство_Продукция?$format=json&$select=Ref_Key,LineNumber,Номенклатура_Key,Количество&$filter=Ref_Key eq guid'1ca586ac-f1db-11f0-957f-9ee51454587f'`
- У заказа есть позиции продукции с информацией о номенклатуре и количестве

### Связанные документы "Сборка запасов"
- Запрос: `GET /Document_СборкаЗапасов?$format=json&$select=Ref_Key,Number,Date,Posted,DeletionMark,ЗаказНаПроизводство_Key,ДокументОснование,ДокументОснование_Type&$filter=ЗаказНаПроизводство_Key eq guid'1ca586ac-f1db-11f0-957f-9ee51454587f'`
- Найдено 8 документов, подтверждающих частичное выполнение заказа

Для новых документов выпуска, создаваемых из PRODPLAN, связь с заказом должна быть не только через `ЗаказНаПроизводство_Key`, но и через основание:

- `ДокументОснование = <Ref_Key Document_ЗаказНаПроизводство>`
- `ДокументОснование_Type = StandardODATA.Document_ЗаказНаПроизводство`

## Структура данных для остатков к выпуску

Для заказа ЗСНФ-000070:
- Запланированное количество: из табличной части "Продукция" заказа
- Фактически выпущенное: из документов "Сборка запасов"
- Остаток к выпуску: `remaining_qty = max(ordered_qty - produced_qty, 0)`

## Рекомендации

1. Фильтр активных заказов: `СостояниеЗаказа_Key ne guid'ad28565a-991b-11eb-e39a-fa163e61326a'`
2. Для частично выполненных заказов использовать данные из табличной части "Продукция" и связанных документов "Сборка запасов"
3. Учитывать остатки к выпуску: `remaining_qty = max(ordered_qty - produced_qty, 0)`
