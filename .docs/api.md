# Целевой API

API разделён по владельцам данных. Роут не вычисляет величины другого домена.

Это целевой контракт, а не перечень уже реализованных endpoint. Фактический
контракт текущей версии фиксируется сгенерированным OpenAPI. Ручные
`/v1/dbr/*`, DBR-программы и запросы барабана с `program_id` удалены.
Очередь сборки читается через
`GET /v1/production-control/assembly-queue`.
Сохранённый барабан принятого поколения читается через
`GET /v1/production-control/drum`.
Сохранённые полки и вытягивание мехцеха читаются через
`GET /v1/production-control/shelves`.

## Планы

- создание и редактирование `draft`;
- одно атомарное действие фиксации;
- чтение неизменяемого снимка;
- явное закрытие.

Повторного MRP, ре-аллокации и ручного создания программы барабана нет.

## Item Ledger

- чтение физической ленты;
- чтение остатка на cutoff;
- чтение активных резервов и адресно-FIFO событий выполнения;
- административное построение, проверка и публикация поколения.

## Очередь сборки и барабан

- чтение общей очереди всех живых планов;
- явное построение кандидата раскладки;
- атомарная публикация раскладки;
- чтение опубликованного борда.

В целевом API запрос не принимает `program_id` и не создаёт ручную программу
выпуска.

## Полки и вытягивание

- чтение и настройка устойчивого справочника полок;
- чтение опубликованной проекции target/остатка/первой нехватки;
- чтение очереди мехцеха с количеством, сроком, приоритетом и защищаемыми
  плитками;
- материализация выбранного количества в производственный заказ.

Пересчёт полок не создаёт новую MRP-потребность.

## Журналы

- журнал производства фильтрует рабочие строки `make`;
- журнал закупки фильтрует рабочие строки `buy`;
- материализация создаёт исполнительный документ из выбранных рабочих строк;
- состояние заказа читается отдельно от физического выполнения.

## Общий контракт ответа

Любой ответ с физическими или расчётными величинами содержит:

```text
ledger_generation
cutoff
truth_status
unavailable_reason
```

GET не запускает тяжёлый расчёт. При `truth_status != accepted` зависимые
количества недоступны.

Read-endpoint возвращает страницу в готовом для отображения виде:

- серверную фильтрацию, сортировку и пагинацию;
- готовые строковые показатели и статусы;
- готовый `summary`;
- готовые флаги разрешённых действий;
- метаданные истины и недоступности.

Frontend не должен получать сырой набор строк с расчётом итогов на клиенте.
