# План: подбор попутного комплекта раскроя при запуске заказа

Дата: 2026-07-20.

## Цель

При запуске производственного заказа на заготовку из трубы или кругляка
предлагать попутный комплект более коротких заготовок из актуального дефицита.
Комплект должен максимально использовать стандартную шестиметровую палку и
снижать расчётный неделовой остаток.

Это рекомендательный расчёт в момент запуска. Отдельный склад, реестр,
штрихкодирование и хранение фактических деловых остатков не создаются.

## Границы первой версии

- стандартная длина исходной палки: 6000 мм;
- длины заготовок берутся из действующих спецификаций;
- кандидаты берутся только из актуального дефицита деталей;
- материал кандидата должен точно совпадать с материалом запускаемой детали:
  номенклатура, профиль/диаметр, толщина и марка, если она задана;
- система не создаёт прогнозный склад обрезков и не переносит остаток между
  запусками;
- результат действует только для текущего подтверждения запуска;
- без подтверждения пользователя попутные количества не запускаются.

## Сценарий

1. Пользователь выбирает заказ и количество к запуску.
2. Система определяет материал, длину основной заготовки, припуск и ширину реза.
3. Рассчитывается базовая раскладка основной детали по палкам 6000 мм.
4. Для свободных интервалов система выбирает заготовки того же материала,
   по которым существует подтверждённый дефицит.
5. Количество каждого кандидата ограничивается его незакрытым дефицитом.
6. Пользователь видит предложенный комплект и раскладку по палкам.
7. После подтверждения запускаются основной заказ и выбранные попутные
   количества; отказ оставляет обычный одиночный запуск.

## Правила подбора

Жёсткие ограничения:

- суммарная длина заготовок, резов и припусков не превышает 6000 мм;
- нельзя предлагать позицию без однозначной длины в спецификации;
- нельзя превышать дефицит кандидата;
- нельзя смешивать разные исходные материалы;
- исключаются закрытые, удалённые и уже полностью обеспеченные потребности;
- одна потребность не должна одновременно резервироваться двумя
  неподтверждёнными комплектами.

Приоритет оптимизации:

1. сохранить приоритет и срок основной запускаемой позиции;
2. закрывать наиболее срочный дефицит попутных деталей;
3. минимизировать количество используемых шестиметровых палок;
4. минимизировать суммарный остаток текущего комплекта;
5. ограничивать число разных попутных позиций, чтобы карта раскроя оставалась
   исполнимой на участке.

## Входные данные

- запускаемый производственный заказ и количество;
- действующая спецификация и компонент исходного материала;
- длина заготовки в миллиметрах;
- стандартная длина палки;
- ширина реза и технологический припуск;
- актуальные незакрытые дефициты деталей;
- сроки, приоритеты и уже запущенные количества.

Если длина заготовки сейчас хранится только в тексте наименования, первая версия
не должна регулярно разбирать её эвристикой. Нужен однозначный числовой атрибут
спецификации или подтверждённое отображение существующего реквизита 1С.

## Результат расчёта

Предпросмотр содержит:

- число целых палок;
- раскладку каждой палки по заготовкам;
- основное и попутные количества;
- длину резов и припусков;
- остаток по каждой палке и общий коэффициент использования;
- исходный дефицит и величину его покрытия для каждого кандидата;
- предупреждения о неполных или неоднозначных данных.

## Интеграция с запуском

Расчёт выполняется перед существующим подтверждением запуска заказа. Предлагаемый
комплект является единым preview-объектом с коротким сроком жизни. На
подтверждении сервер обязан повторно проверить дефициты и доступность
потребностей, после чего материализовать только подтверждённые количества через
штатный механизм запуска.

Расчёт не меняет физический остаток материала сам по себе. Списание и фактический
расход остаются в существующем контуре 1С/PRODPLAN.

## Шов с ядром пополнения

Источник кандидатов — сохранённая потребность пополнения из
`reservation-replenishment-core.md`. Оптимизатор раскроя не выполняет
собственный взрыв BOM и не корректирует резерв.

Для строки потребности:

```text
replenishment_remaining_qty =
    max(replenishment_required_qty - replenishment_received_qty, 0)
eligible_deficit =
    max(
        replenishment_remaining_qty
        - confirmed_open_production_qty,
        0,
    )
```

Попутный запуск может покрыть только `eligible_deficit`.

`confirmed_open_production_qty` имеет то же значение, что в контракте полок:
это незакрытое количество исполнительных строк данного требования с
подтверждённым сроком и складом назначения.

Правила владения:

- `ReservationEntry` остаётся единственным источником зафиксированной
  потребности и FIFO-выполнения;
- раскрой создаёт обычное собственное производственное покрытие через штатный
  механизм запуска и его связь с исходной MRP-потребностью;
- preview раскроя ничего не записывает в леджер;
- подтверждение комплекта повторно читает актуальный ledger и уменьшает
  попутное количество, если дефицит уже покрыт другим запуском;
- строки закрытого плана кандидатами не являются.

Таким образом, подбор комплекта является способом материализации уже
существующего дефицита, а не новым планировщиком потребности.

## Расчётное ядро

Это ограниченная задача одномерного раскроя. Для первой версии достаточно
детерминированного bounded-knapsack/динамического алгоритма с дискретностью 1 мм
и ограниченным набором ближайших дефицитных кандидатов. Жадный подбор только по
длине не использовать: он нестабилен и часто даёт хуже заполненные палки.

Ядро должно быть чистой функцией без SQLAlchemy и сетевых вызовов. Отдельно
тестируются:

- точное заполнение палки;
- учёт ширины реза и припуска;
- ограничение дефицитом;
- несколько одинаково хороших вариантов;
- приоритет срочной детали при равном использовании;
- отсутствие совместимых кандидатов;
- повторная серверная проверка при одновременном запуске.

## Этапы

1. Аудит источника длины заготовки, стандартной длины, реза и припуска.
2. Read-only preview для одной палки и одного основного заказа.
3. Подбор нескольких попутных позиций по актуальному дефициту.
4. UI карты раскроя и ручное включение/исключение предложенных строк.
5. Атомарное подтверждение и запуск комплекта.
6. Shadow-проверка на фактических заказах участка до включения материализации.

## Критерий готовности

Мастер при запуске заказа получает понятный и воспроизводимый комплект,
не превышающий актуальные дефициты. Система показывает раскрой шестиметровых
палок и расчётный остаток, но не требует вести склад отдельных обрезков.
