# PRODPLAN: Архитектура системы (Актуальная версия)

**Версия:** 3.0
**Дата:** 2025-11-28

## 🏗️ Архитектурная схема

PRODPLAN использует современную архитектуру, состоящую из трех основных компонентов, работающих в Docker-контейнерах:

```
┌─────────────────┐   ┌────────────────────────┐   ┌─────────────────────┐   ┌────────────────┐
│   Пользователи  │──▶│       Frontend         │──▶│       Backend       │──▶│   База данных  │
│ (Веб-браузер)   │   │ (Quasar, Vue.js, TS)   │   │ (FastAPI, Python)   │   │  (PostgreSQL)  │
└─────────────────┘   └────────────────────────┘   └─────────────────────┘   └────────────────┘
         ▲                     │                           ▲
         │                     ▼                           │
         └─────────────────────┴───────────────────────────┘
                               │
                        ┌──────────────┐
                        │  1С система  │
                        │ (OData API)  │
                        └──────────────┘
```

-   **Frontend**: Одностраничное приложение (SPA) на **Quasar (Vue.js + TypeScript)**. Отвечает за пользовательский интерфейс. Запускается в Docker-контейнере и доступно на порту **9000**.
-   **Backend**: API-сервер на **FastAPI (Python)**. Реализует всю бизнес-логику, включая расчеты MRP, взаимодействие с базой данных и синхронизацию с 1С. Доступен на порту **8000**.
-   **База данных**: **PostgreSQL**, хранящая все данные системы.
-   **1С система**: Внешний источник данных (ERP), с которым Backend общается по **OData API** для синхронизации номенклатуры, спецификаций, заказов и остатков.

## 🔧 Ключевые модули Backend (`backend/app/services/`)

Бизнес-логика системы сосредоточена в сервисном слое. Ключевые сервисы:

| Сервис | Назначение |
|---|---|
| `planning_service.py` | **Основной сервис MRP**. Отвечает за запуск и управление процессом планирования. |
| `order_quantity_calculator.py` | Расчет оптимальных размеров партий (лот-сайзинг). |
| `capacity_scheduler.py` | Планирование загрузки производственных мощностей. |
| `pegging_builder.py` | Построение связей "потребность-источник" (pegging). |
| `odata_client.py` | Клиент для взаимодействия с OData API 1С. |
| `*_sync.py` (напр. `nomenclature_sync.py`) | Сервисы для синхронизации конкретных сущностей с 1С. |
| `plan_service.py` | Управление планами производства (старая логика). |

## 🌐 Ключевые модули Frontend (`frontend/src/`)

Интерфейс построен на компонентном подходе с использованием современных практик Vue 3.

| Директория | Назначение |
|---|---|
| `pages/MRPResultPage.vue` | Страница для просмотра результатов MRP-расчета. |
| `pages/MRPRunsPage.vue` | Страница для запуска и просмотра истории прогонов MRP. |
| `components/mrp/` | Компоненты, специфичные для интерфейса MRP (таблицы, карточки, фильтры). |
| `composables/use*.ts` | Изолированная логика для работы с данными (получение, форматирование). |
| `services/api.ts` | Централизованный клиент для отправки запросов к Backend API. |
| `stores/mrpResults.ts` | Хранилище Pinia для управления состоянием результатов MRP. |
